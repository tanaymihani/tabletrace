# Labels

`ground_truth.csv` has 514 property values from 20 tables in 10 documents. It's generated by
`transcriptions.py`, which has every labeled table typed in as a small grid, so each row in the CSV
can be traced back to a line in that file and from there to the page.

## How the labels were made

- Every table was transcribed from a rendered page image (300 DPI for the scans, with zoomed crops
  for dense or damaged cells), before any pipeline output existed.
- The born-digital tables were then checked against their text layer, after removing the hidden
  duplicate text described at the bottom of this page. The scanned tables were checked against the
  OCR layer that comes inside the PDF, which is noisy but independent.
- Values in canonical units (HV, MPa, %) are computed from the printed number and unit using a small
  conversion table in `transcriptions.py`. I kept it separate from the pipeline's pint-based
  normalizer on purpose, so a bug in one can't hide in the other.

## Rules

| Question | Decision |
|---|---|
| Which properties | Vickers hardness, yield strength (0.2% offset, Rp0.2, σy, σ0.2, YS), ultimate strength (UTS, Rm, σmax, UCS) and elongation (A, ε, εf, εmax, EL, fracture strain, strain to failure). Tension and compression both count. `loading` records which one when the table or caption says. |
| What's left out | Values marked as calculated, predicted or theoretical (Calc in Yao 2016, "predicted" in Rickman 2019, A calc. in Zýka 2019, σc and σm in Tseng 2018), summary rows ("Averages"), empty cells, and other properties (E, density, reduction of area). |
| `material` | The sample name as printed: the cell in the label column, or the column header in transposed tables. Citations and footnote marks are dropped and subscripts are written inline (`Nb1.5TaTiZr0.5`). When the label column holds test temperatures instead, the sample is named by the sub-header (`CC`, `DS`). |
| Literature values | Included when they're printed in the table (Zýka 2019 Table 7 rows from ref. [25], the pure-metal columns in Yao 2016), and marked in `notes`. |
| Bounds and footnotes | `> 50` is stored as 50 with qualifier `>`. `*1190` (estimated from a figure) and `9.1*` (broke outside the gauge marks) keep their value, and the mark is explained in `notes`. |
| Replicates | Unlabeled replicate rows in NASA TM X-3216 get the alloy name from the row above, with `condition = replicate 2`. |
| Test temperature | Stored in °C when the table prints it (`~23 °C`, `-423 °F`, or a temperature group header). Left blank when the table only says "room temperature". |

## Checks

Three checks against independent sources cover 255 of the 514 values. None of them required
changing a label.

| Check | Values covered | Result |
|---|---|---|
| LitXAlloy (Radical AI, LitXBench, 2026) curates the same seven journal papers. Matching is one-to-one on property and value within 1%. | 102 LitXAlloy values | All 102 agree, and all 74 LitXAlloy values whose source is a table are in these labels. The 6 LitXAlloy values that aren't here come from the text of the paper, not a table. See `reports/label_qa.md`. |
| NASA TM X-3216 prints every UTS twice, in MN/m² and ksi. | 97 UTS values | 96 of 97 agree after converting. The one that doesn't (Ti-50V-1Si at 650 °C: 530 MN/m² next to 79 ksi) is wrong in the source. I confirmed it at 400 DPI and labeled it as printed. |
| NASA TP-3288 Table 2 prints an "Averages" row for each group, so the individual values have to reproduce it. | 56 values | 13 of the 15 group averages match. The two that don't are mistakes in the source, confirmed at 450 DPI: the Ti-5Al-2.5Sn air UTS samples average 108.1 ksi (printed as 108.5, and as 108.4 in Table 4), and the Ti-6Al-4V air 1-inch elongations average 10.8% (printed as 17.4%). |

`make labels` regenerates the CSV and reruns the two internal checks, and `make litx` reruns the
LitXAlloy comparison.

The rest of the values (the patent, the elongation columns of TM X-3216, and Tables 3 and 4 of
TP-3288) were only checked against the page image and the OCR layer in the PDF. `make review`
builds a local page with each labeled table next to its labels, for anyone who wants to check them.

## Second pass

A month after the first pass, 50 labels were drawn at random (seed 20261030) and listed without
their values, only the sample name, property, temperature and condition
(`second_pass/sample.csv`). Each value was then found and read again from a fresh render of the
page (`second_pass/readings.csv`) before comparing. All 50 agree with the printed number in the
labels, which puts a one-sided 95% upper bound of 5.8% on the transcription error rate
(`python labels/second_pass/compare.py`). The sample covers all 10 documents and 19 values
from the typewritten NASA report. It checks reading and locating values. It can't catch a rule
applied the same wrong way twice, since the same person did both passes.

## Problems in the source documents

- **Hidden duplicate tables.** Four of the five MDPI papers (all except Chen 2014) embed a whole page
  of the author's manuscript as a Form XObject so a vector figure can be reused. The viewer clips it
  to the figure, but text extractors ignore the clipping, so the text layer has a second copy of the
  table shifted down by one row. `tables_text.py` drops the characters drawn outside the clip.
- **Typos.** Table 7 in US20020159914A1 reuses the alloy numbers 30 to 34 from Table 6, while the
  text calls them 35 to 39. The labels keep the printed numbers.
